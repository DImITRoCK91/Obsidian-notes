
## 1. Способы управления памятью

|                        | **Ручное (C)**                                  | **Автоматическое (Java, Python, Go, C#)**                   |
| ---------------------- | ----------------------------------------------- | ----------------------------------------------------------- |
| **Контроль**           | Полный: `malloc`/`free`                         | Минимальный: время жизни определяет GC                      |
| **Производительность** | Нет накладных расходов на GC                    | GC нагружает CPU и память (stop-the-world)                  |
| **Предсказуемость**    | Высокая (`free` срабатывает сразу)              | Низкая (момент запуска GC не гарантирован)                  |
| **Ошибки**             | Утечки, висячие указатели, двойное освобождение | Практически отсутствуют (кроме случайного удержания ссылки) |
| **Пригодность**        | Системное ПО, драйверы, встраиваемые системы    | Прикладные приложения, веб-серверы, микросервисы            |

**Суть компромисса:** в C платят временем разработки и риском ошибок за контроль; в Java  ресурсами CPU/памяти за удобство и безопасность.

### Различия GC в Java и Python
- **Java** — граф объектов (reachability analysis): обход достижимых объектов от корневых точек (стек, статические поля), недостижимые помечаются как мусор. Требует stop-the-world, эффективен на больших объёмах.
- **Python** — счётчик ссылок (reference counting): объект удаляется сразу при падении счётчика до нуля; циклические ссылки обрабатывает отдельный GC.

## 2. Три области памяти в JVM

| Область                             | Что хранит                                                                        | Время жизни                                           |
| ----------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------- |
| **Стек (Stack)**                    | Локальные переменные примитивов, **ссылки** на объекты, параметры, адрес возврата | Фрейм разрушается при выходе из метода                |
| **Куча (Heap)**                     | **Все объекты**, созданные через `new`                                            | Пока есть хотя бы одна активная ссылка                |
| **Metaspace** (до Java 8 — PermGen) | Метаданные классов: структура, имена методов, **статические поля**                | Один раз при загрузке класса, на всю работу программы |

### Стек — подробнее
- Каждый вызов метода создаёт **фрейм** в стеке.
- В фрейме: примитивы, ссылки (не сами объекты), параметры, служебная информация.
- Размер ограничен (1 МБ на поток).
- Фрейм автоматически разрушается при выходе из метода.

```java
void example() {
    int x = 10;         // x — примитив, лежит в стеке
    String s = "Hi";    // s — ссылка в стеке, объект "Hi" — в куче
}
```

### Куча — подробнее
- Единая область для **всех объектов**.
- Объект попадает туда при вызове `new`.
- Живёт, пока есть активная ссылка; иначе удаляется GC.
- Размер практически неограничен.

### Metaspace — подробнее
- Хранит метаданные классов и статические поля (`static`).
- Данные попадают туда **один раз** при загрузке класса.

```java
class Config {
    static String appName = "MyApp";  // appName — в Metaspace
    int version;                      // version — в куче
}
```
## 3. Оператор `new`

Аналог `malloc`, но управляемый JVM. Возвращает адрес выделенной памяти. **Никогда не возвращает `NULL`** — при нехватке памяти выбрасывает `OutOfMemoryError`.

```java
Scanner sc = new Scanner(System.in);
```
- `Scanner sc` — объявление переменной-ссылки (тип + имя).
- `new Scanner(System.in)` — выделение памяти в куче + вызов конструктора для инициализации.

**Что происходит:**
1. JVM выделяет память в куче под объект.
2. Вызывается конструктор, который инициализирует объект.

### Когда `new` нужен
- Создание экземпляров классов (`Scanner`, `Random`, `File`, своих классов).
- Создание **массивов** (массивы в Java — объекты в куче):

```java
int[] arr = new int[10];   // массив — объект в куче

int[] numbers;             // ссылка объявлена, память НЕ выделена
// numbers[0] = 5;         // NullPointerException
numbers = new int[5];      // теперь память выделена
```

### Когда `new` не нужен
- Переменные примитивных типов: `int x = 5;`
- Строковые литералы: `"Hello"` (частный случай — интернирование в пул строк).
## 4. Примитивы vs ссылки на объекты

```java
int a = 5;              // a — примитив, значение прямо в стеке
int b = a;              // b — копия значения

Scanner s1 = new Scanner(System.in);
Scanner s2 = s1;        // s2 — копия ссылки на ТОТ ЖЕ объект
```

**Ссылка в Java** — это указатель (адрес), но:
- без обозначений (как `*` в C);
- без арифметики указателей.

### Сравнение `==` для объектов
```java
Scanner s1 = new Scanner(System.in);
Scanner s2 = s1;
Scanner s3 = new Scanner(System.in);

System.out.println(s1 == s2);  // true — одна и та же ссылка
System.out.println(s1 == s3);  // false — разные объекты
```
`==` сравнивает **ссылки (адреса)**, а не содержимое. Для содержимого — `.equals()`.
## 5. Сборщик мусора (Garbage Collector)

В C забытый `free` → утечка. В Java объект удаляется автоматически, когда на него перестают ссылаться:

```java
void example() {
    Scanner sc = new Scanner(System.in);
    // ... используем sc ...
}   // ← sc выходит из области видимости, ссылка теряется, GC может удалить объект
```

**Свойства GC:**
- Запускается автоматически, когда JVM решит.
- Не удаляет объекты с активными ссылками.
### Когда объект становится мусором
1. Переменная со ссылкой вышла из области видимости.
2. Переменной присвоили другую ссылку (`sc = null` или `sc = otherScanner`).
3. На объект ссылаются только другие объекты-мусор (цикл ссылок — GC справляется, в отличие от C).
## 6. Передача параметров в методы

В Java **все параметры передаются по значению**:
- Для примитивов копируется значение.
- Для ссылок копируется **ссылка** (адрес), объект остаётся в куче.

```java
void swap(int x, int y) {
    int t = x; x = y; y = t;   // меняются копии, исходные НЕ изменятся
}

void rename(Scanner sc) {
    sc = new Scanner(System.in); // меняется локальная ссылка, исходная — нет
}
```

Но **объект через ссылку изменить можно**:
```java
void setValue(int[] arr) {
    arr[0] = 42;   // меняется содержимое объекта в куче
}
```
## 7. Сравнение C — Java — Python

| Аспект | C | Java | Python |
|---|---|---|---|
| Выделение памяти | `malloc(size)` | `new Type()` | создание объекта (неявно) |
| Освобождение | `free(ptr)` | сборщик мусора | сборщик мусора |
| Ошибка памяти | утечки, dangling pointers | `OutOfMemoryError` | `MemoryError` |
| Переменная хранит | значение / указатель | значение / ссылку | ссылку на объект |
| Массивы | блок памяти (указатель) | объект в куче | список / tuple |
| Вручную вызвать GC | — | `System.gc()` (не гарантирует) | `gc.collect()` |
| Арифметика указателей | да | **нет** | нет |
| Примитивные типы | `int`, `double` на стеке | `int`, `double` на стеке | всё — объект |
