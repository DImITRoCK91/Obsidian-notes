## 1. Модель Java: исходный код → байт-код → JVM

**Этапы:**

1. **Компиляция:** Компилятор `javac` транслирует исходный код (`.java`) не в машинный код, а в **байт-код** (`.class`) — промежуточное представление для «виртуальной машины» .
	
2. **Загрузка и выполнение:** Байт-код загружается и исполняется **JVM** (Java Virtual Machine). JVM либо интерпретирует байт-код, либо компилирует его в машинный код «на лету» с помощью **JIT-компилятора** (Just-In-Time) .

**Ключевая идея:** Байт-код не привязан к конкретной аппаратной архитектуре. Один и тот же `.class` файл может работать на любой платформе, где установлена соответствующая JVM. Это принцип **«Write Once, Run Anywhere»**.

Немного истории:
**«Write Once, Run Anywhere»** - знаменитый рекламный слоган, который был представлен компанией Sun Microsystems в 1995 году для описания кроссплатформенных преимуществ языка.

## 2. Модель C: исходный код → машинный код

**Этапы:**

1. **Компиляция:** Компилятор (например, `gcc`) транслирует исходный код (`.c`) напрямую в **объектный код** (машинные инструкции для конкретного процессора).
    
2. **Компоновка (Линковка):** Компоновщик (Linker) собирает объектные файлы и библиотеки в единый **исполняемый файл** для данной ОС и архитектуры.
    
3. **Запуск:** Операционная система загружает исполняемый файл в память и передаёт управление процессору напрямую.

Результат компиляции C - это машинный код. Он выполняется максимально быстро, но **непереносим** между разными архитектурами (например, код для x86 не запустится на ARM) .

Итоговые различия:
- **C** компилируется напрямую в машинный код конкретной платформы. Результат - быстрый, исполняемый файл, но он привязан к архитектуре процессора и ОС: для другой платформы нужна повторная компиляция.
    
- **Java** компилируется в промежуточный байт-код, который исполняет JVM. Это даёт переносимость («написано один раз - работает везде»), но добавляет слой виртуальной машины. Скорость частично компенсируется JIT-компиляцией во время выполнения.
