
# Что такое Git

Git - система контроля версий. Позволяет: отслеживать изменения файлов, возвращаться к  предыдущим версиям, работать в команде над одним проектом.

# Установка Git

1) Нужно перейти на сайт https://git-scm.com/install/windows и загрузить установщик
2) Выставить параметры установки и установить git на компьютер
3) Можно проверить версию git при помощи команды **git --version**

# Обязательная первоначальная настройка

1) Нужно указать имя пользователя и email (тот же, что и на GitHub/GitLab, потому что в будущем пригодится для отправки нашего репозитория на удалённый сервер)
```bash
# Имя пользователя
git config --global user.name "Ваше Имя"
# Email (тот же, что на GitHub/GitLab)
git config --global user.email "you@example.com"

# Задайте имя и email только для этого репозитория
git config --local user.name "Ваше имя"
git config --local user.email "you@example.com"
```
2) Через **git config --list** можно посмотреть текущие настройки, какие заданы имя пользователя, почта

# Git - полная шпаргалка по работе
Git на каждый день // Основные команды, которые используются очень часто
```bash
git init # создание репозитория с нуля

git status # полный статус гита

git add . # добавить всё в текущей папке в репо
git add yourcode.c # добавить конкертные файлы в репо, если несколько файлов, чтобы их разделить достаточно поставить пробел

# Создание коммитов
git commit -m "Ваш комментарий" # создание коммита с комментарием
git commit -am "Ваш комментарий" # add+commit для отслеживаемых файлов
git commit --amend -m "Ваш новый комментарий" # изменение сообщения последнего коммита
# Обычно в комментариях пишут, что было изменено, какие ошибки были исправлены и т.п.

# Просмотр истории
git log # полный просмотр
git log --oneline # краткий просмотр 
 
git diff # изменения в рабочей дирректории

# Удаление коммитов
git reset --soft HEAD~1 # команда для удаления последнего коммита, но при этом оставив последние изменения в файлах
git reset --hard  HEAD~1 # команда для удаления последнего коммита, но при этом все изменения будут утерены

# Удаление файлов
git rm yourcode.c # Удаление файлов из рабочей директории и из Git
git rm --cached yourcode.c # удаление только из Git, будет убран из отслеживания

# ВЕТКИ
git branch # список локальных веток
git branch feature # создать ветку (без перехода)
git switch feature # перейти (современный способ)
git switch -c feature # создать + перейти
git branch -m new-name # переименовать текущую
git merge feature  # команда, которая объединяет изменения из одной ветки в другую
```
Также стоит упомянуть про конфликты объединения веток в Git. Конфликт возникает, когда Git не может автоматически объединить изменения из двух веток.  Это происходит, когда в одном и том же месте файла были сделаны разные изменения в обеих ветках.

# GitHub
GitHub — это платформа, которая поддерживает весь процесс разработки программного обеспечения, от планирования работы до развертывания и эксплуатации программного обеспечения.
GitHub создает Git, размещая проекты Git, называемые **репозиториями**, в облаке, а также добавляя средства планирования и совместной работы, которые упрощают совместную работу команд.

```bash
git remote add origin git@github.com:user/repo.git # команда, чтобы связать локальный проект с удалённым
git push -u origin main # команда для отправки кода в облако, main - название основной ветки (изначально основная ветка называется master, лучше её переименовать в main)

git clone <url> # команда, чтобы полностью скопировать репо

git push # команда для отправки коммитов на сервер
git pull # команда для загрузки чужих коммитов с сервера
```
