**Стандарт оформления кода (стиль программирования)** - это единый набор правил написания исходного кода, который упрощает его чтение, снижает нагрузку на память и ускоряет командную работу.

Среди доступных руководств по стилю для Java **Google Java Style Guide** выделяется как наиболее практичный и широко используемый стандарт, ориентированный на жёсткие, проверяемые правила, а не на субъективные советы.
## 1. Основы исходных файлов

| Аспект           | Рекомендация                                                            |
| ---------------- | ----------------------------------------------------------------------- |
| **Кодировка**    | Всегда **UTF-8**                                                        |
| **Имя файла**    | Совпадает с именем единственного top-level класса + `.java`             |
| **Отступы**      | **Только пробелы**, табуляция запрещена. Размер отступа — **2 пробела** |
| **Длина строки** | Не более **100 символов**                                               |

## 2. Структура файла (строгий порядок)

1. Лицензия / копирайт (если есть)
    
2. `package` (без переноса строк)
    
3. `import` (без wildcard `*`, без переноса, сортировка по ASCII, статические импорты отдельно)
    
4. Ровно **один** top-level класс
    

Между секциями — ровно одна пустая строка.
## 3. Форматирование блоков (K & R стиль)

Немного истории:
K&R style (стиль Кернигана и Ричи) — это один из самых известных способов оформления и расстановки фигурных скобок {} в коде программ, изначально описанный авторами языка Си Брайаном Керниганом и Деннисом Ричи в их культовой книге «Язык программирования C».
"Информация взята с ИИ поисковика Google" 

**Фигурные скобки**:

- Открывающая `{` — на той же строке, что и объявление
    
- Закрывающая `}` — на отдельной строке (кроме пустых блоков `{}`)
    
- `else` / `catch` — на той же строке, что и закрывающая `}`
    

**Пустые блоки** допустимы в краткой форме: `{}` (без переноса), если блок действительно пуст.

**Операторы**:

- Один оператор на строку
    
- Обязательные пробелы вокруг бинарных операторов, после запятых, перед `{`
    
- Группирующие скобки в выражениях — **рекомендуются**
## 4. Именование

| Сущность                                  | Стиль                              | Пример                               |
| ----------------------------------------- | ---------------------------------- | ------------------------------------ |
| Пакеты                                    | `lowercase`, без подчёркиваний     | `com.example.myapp`                  |
| Классы / интерфейсы                       | `UpperCamelCase` (существительные) | `OrderService`, `HttpClient`         |
| Методы                                    | `lowerCamelCase` (глаголы)         | `sendMessage()`, `calculateTotal()`  |
| Константы (`static final` + неизменяемые) | `UPPER_SNAKE_CASE`                 | `MAX_RETRY_COUNT`, `DEFAULT_TIMEOUT` |
| Поля (не константы)                       | `lowerCamelCase`                   | `userName`, `totalAmount`            |
| Параметры / локальные переменные          | `lowerCamelCase`                   | `userId`, `result`                   |
| Переменные типа                           | `T`, `E`, `K`, `V` или `RequestT`  | —                                    |

Уточнение: локальные переменные не считаются константами, даже если объявлены final - для них используется lowerCamelCase, а не UPPER_SNAKE_CASE . Также: тестовые методы JUnit могут содержать подчёркивания для разделения логических частей, например transferMoney_deductsFromSource().

## 5. Объявления переменных и массивов

- **Одна переменная на объявление**: `int a, b;` — запрещено
    
- **Объявление как можно ближе к использованию** (не в начале блока)
    
- **Массивы**: скобки относятся к типу, а не к переменной:
    
    - String[] args - верно
        
    - String args[] - неверно
## 6. Специальные символы и escape-последовательности

- Для символов с готовой escape-последовательностью (`\n`, `\t`, `\"`, `\\` и т.д.) использовать именно её, а не восьмеричный или Unicode-код
