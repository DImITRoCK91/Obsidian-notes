
## 1. Общий синтаксис

```java
условие ? выражение1 : выражение2
```

- **`условие`** — выражение типа `boolean` (не обязательно примитив — может быть `Boolean`, с автоупаковкой/распаковкой).
- **`выражение1`** — вычисляется, если условие `true`.
- **`выражение2`** — вычисляется, если условие `false`.
- Оба выражения должны быть **совместимы по типу** (см. п. 3).
- Оператор **правосвязывающий** (right-associative): `a ? b : c ? d : e` читается как `a ? b : (c ? d : e)`.

**Приоритет:** ниже, чем у логических (`&&`, `||`), но выше, чем у присваивания (`=`, `+=` и т.п.). Поэтому вложенные тернарники и присваивания часто требуют скобок для читаемости.

---

## 2. Использование в составе выражений

Тернарный оператор — это **выражение**, а не инструкция. Оно возвращает значение, поэтому его можно встраивать куда угодно:

### a) Присваивание
```java
int max = (a > b) ? a : b;
String role = isAdmin ? "admin" : "user";
```

### b) Аргумент метода
```java
System.out.println(count == 0 ? "пусто" : "элементов: " + count);
```

### c) Возврат из метода
```java
public int abs(int x) {
    return x >= 0 ? x : -x;
}
```

### d) Внутри другого выражения
```java
int total = price * (discount ? 0.9 : 1.0) + (express ? 500 : 0);
```

### e) Вложенные тернарники (цепочка)
```java
String grade = score >= 90 ? "A"
             : score >= 75 ? "B"
             : score >= 60 ? "C"
             : "F";
```

### f) В лямбдах и стримах
```java
list.stream()
    .map(s -> s.isEmpty() ? "N/A" : s)
    .collect(Collectors.toList());
```

### g) В составе условия (с осторожностью)
```java
if ((x > 0 ? y : z) > 10) { ... }   // скобки обязательны для читаемости
```

---

## 3. Использование «без выражений» (как инструкции)

Тернарный оператор **не является инструкцией** — его нельзя использовать как самостоятельный оператор, если результат никуда не присваивается:

```java
// НЕ КОМПИЛИРУЕТСЯ:
// a > b ? doX() : doY();
```

Однако его можно применять там, где выражение допускается как «действие»:

```java
// Допустимо: вызов метода-выражения внутри тернарника
System.out.println(flag ? "on" : "off");

// Допустимо: побочный эффект в ветвях (не рекомендуется)
flag ? list.add(a) : list.add(b);   // компилируется: метод возвращает boolean/void?
```

⚠️ **Важно:** если ветви возвращают `void` (например, `list.add(...)` возвращает `boolean` — ок; но `void`-метод — нет):

```java
// НЕ КОМПИЛИРУЕТСЯ, если метод возвращает void:
// flag ? voidMethod1() : voidMethod2();
```

Для побочных эффектов **правильнее использовать `if/else`** — тернарник предназначен для **выбора значения**, а не для управления потоком.

## 4. Правила типов результата (важно для экзамена)

Тип результата тернарного выражения определяется по правилам **binary numeric promotion** и совместимости ссылочных типов:

1. **Примитивы разного типа** → расширение до «старшего» типа:
   ```java
   int x = true ? 1 : 2L;        // результат long → нужен приведение к int? нет: int x = ... ошибка
   long y = true ? 1 : 2L;       // ok, long
   ```
   Точнее: `int` и `long` → `long`; `int` и `double` → `double`; и т.д.

2. **Примитив и его обёртка** → автоупаковка/распаковка:
   ```java
   Integer r = true ? 1 : null;  // ok: Integer
   int r2 = true ? Integer.valueOf(1) : 2; // распаковка → int
   ```

3. **Ссылочные типы** → наименьший общий супертип (LUB):
   ```java
   Object o = flag ? "str" : Integer.valueOf(1); // Object
   Number n = flag ? 1 : 2.0;                    // Double (не Number!)
   ```

4. **`null` и ссылочный тип** → ссылочный тип:
   ```java
   String s = flag ? "x" : null; // ok
   ```

5. **Осторожно с `null` и примитивом** → NPE при распаковке:
   ```java
   int x = flag ? 1 : null;   // компилируется? Нет — несовместимые типы (int и null)
   Integer boxed = flag ? 1 : null; // ok
   int y = boxed;             // NPE, если null
   ```

## 5. Особенности и подводные камни

| Ситуация | Поведение |
|---|---|
| Вложенность без скобок | Правоассоциативно: `a?b:c?d:e` = `a?b:(c?d:e)` |
| Смешение `int`/`long`/`double` | Приведение к старшему типу — возможна потеря точности/ошибка компиляции при присваивании |
| `Boolean`-обёртка в условии | Автораспаковка; `null` → **NPE** |
| Ветви с `void`-методами | Не компилируется (void не выражение) |
| Тернарник как инструкция | Не компилируется без присваивания/использования |
| Побочные эффекты в ветвях | Технически возможны, но стилистически плохо — используйте `if/else` |
| Читаемость | Глубокая вложенность (>2 уровней) ухудшает читаемость; лучше `switch` или `if/else` |

---

## 6. Сравнение с `if/else`

| Критерий | Тернарный оператор | `if/else` |
|---|---|---|
| Возвращает значение | ✅ да | ❌ нет (инструкция) |
| Использование в выражении | ✅ да | ❌ нет |
| Побочные эффекты / ветвление логики | ⚠️ возможно, но не рекомендуется | ✅ да |
| Читаемость при сложной логике | ❌ падает | ✅ лучше |
| Краткость для простого выбора | ✅ да | ❌ многословно |

**Правило стиля:** тернарник — для **простого выбора одного из двух значений**; `if/else` — для **управления потоком** и побочных эффектов.

## 7. Примеры (сводка)

```java
// 1. Простое значение
int max = (a > b) ? a : b;

// 2. Строка
String msg = ok ? "success" : "failure";

// 3. Вложенность
String size = n < 10 ? "small" : n < 100 ? "medium" : "large";

// 4. В выражении
double cost = base * (vip ? 0.8 : 1.0);

// 5. В аргументе
print(flag ? "yes" : "no");

// 6. С null (ссылочный тип)
String name = input != null ? input : "default";

// 7. Опасный случай (NPE)
Boolean b = null;
// int x = b ? 1 : 2;  // NullPointerException при распаковке
```

## 8. Ключевые тезисы для запоминания

1. Тернарный оператор — **выражение**, а не инструкция.
2. Синтаксис: `cond ? exprTrue : exprFalse`, условие — `boolean`.
3. Правосвязывающий, приоритет между `||` и `=`.
4. Тип результата — по правилам numeric promotion / LUB для ссылок.
5. `null` в условии-обёртке → **NPE**.
6. Ветви не могут быть `void`.
7. Для побочных эффектов и сложной логики — **`if/else`**, не тернарник.
8. Вложенность >2 уровней — плохой стиль.
